# T004e — 煎锅台放置预览（影子 + 放不下时的红"x"）

> 给 Codex：先读 `AGENTS.md`，再读本说明书，再读 `docs/GDD.md` §5.5.1 里"放置预览"那一条。T004 煎锅台已完成，搬运逻辑在 `Assets/_MMF/Scripts/Player/PlayerInteractor.cs` 的 `Lift()`。
> 这是一个**小任务**：只做"举着锅台时显示要放下的位置"这一件事。

## 目标
举着锅台时，玩家前方**会放下的那一格**一直显示一个半透明的锅台影子。那一格放不下时，影子上面再叠一个红色"x"。

## 规则
- **什么时候显示**：只要在举着锅台，就一直显示；放下或没在举的时候隐藏。
- **位置**：和点左键时**实际会放下的位置完全一样**，也就是玩家最后移动方向前方 1 格，对齐车内格子。玩家转向或走动时，影子要每帧跟着更新。
- **样子**：和锅台同样的 Sprite、同样大小、同样颜色，但半透明，**alpha 0.5** 🟡（做成 Inspector 可调参数）。以后锅台换成图片时，影子要自动用同一张图：从锅台的 SpriteRenderer 读 sprite，不要单独存一份。影子不能有碰撞体。
- **放不下时**（目标格不完全在车内、和墙或玩家重叠）：影子照常显示，**上面叠一个红色"x"**，用的图和头顶"x"相同（`Art/Placeholder/Failure.png`）。
- **放不下时点左键**：没反应，继续举着。头顶**不要**闪"x"（这和现在的行为一样，保持）。
- 显示顺序：影子画在地板之上；红"x"在影子之上；都在玩家和举着的锅台之下。

## 实现要求
- "目标格在哪"和"能不能放"现在写在 `Lift()` 里面。把它抽成**一个**方法（例如 `TryGetPlacement(out Vector2 cell)`，返回能不能放，同时给出格子），**预览和 `Lift()` 都调用它**，保证影子的位置和真正放下的位置不会不一样。不要复制一份同样的逻辑。
- 现在的检测用了 `Physics2D.OverlapBoxAll`，每次调用都会分配数组。预览每帧都要检测，所以改用不分配内存的写法：`Physics2D.OverlapBox` 加一个预先分配好的 `Collider2D[]`，或者 `ContactFilter2D` 加一个复用的 List。检测时要忽略影子自己（影子本来就没有碰撞体）。
- 场景生成器 `MMF/Build Prototype Scene` 负责生成影子和红"x"，并接好引用。继续使用"新建场景后再加载资源、保存后重新打开检查引用"的做法。
- 新脚本最多 1 个（例如 `MMF.Player.PlacementPreview`），也可以直接加在现有组件里，你来定。

## 验收标准
- [ ] 编译无报错无警告；场景生成 3 次，引用都不为空；现有 27 个 EditMode 测试全部通过

## 给用户的试玩步骤
1. 菜单 `MMF → Build Prototype Scene` → Play → 点一下 Game 窗口。
2. 在锅台旁点左键把它举起来，四处走动和转向，看前方的影子。
3. 走到靠墙或者车门口，影子上出现红"x"；点左键放不下。
4. 在空地上点左键，锅台落在影子的位置。
