# T005a2 — 怪物改目标：追玩家 / 去车头车尾，被墙挡住时沿墙滑

> 给 Codex：先读 `AGENTS.md`（尤其是 "Good structure, minimal changes"），再读本说明书，再读 `docs/GDD.md` **§5.8.1 的"行为"部分**。T005a 已完成：`Assets/_MMF/Scripts/Combat/Monster.cs` 现在**直线朝餐车中心**走。
> 这是**小任务**，只改"怪物往哪走"。不做武器（T005b）、不做掉落（T005c）。

## 为什么改
怪物朝餐车中心走，会停在门口外面把门堵住，玩家出不去。用户改了设计：怪物不再去车门，而是追玩家，或者去车头、车尾。

## 规则（🟡 = 必须做成可调参数，放进 `MonsterDefinition`）
| 情况 | 怪物去哪 |
|---|---|
| 玩家在**车外**，且离这只怪 **≤ 8** 🟡 | **追玩家**（朝玩家的位置走） |
| 正在追，玩家离开到 **> 10** 🟡 | 放弃，改去车头 / 车尾 |
| 玩家在**车里**（`TruckArea.Contains`） | 去车头 / 车尾（不管距离） |
| 不在追的其他时候 | 去车头 / 车尾 |

- **车头在右边（+x）、车尾在左边（−x）**。目标点是那一端外墙**外侧正中**（贴着墙停下，不会靠近上下两个门）。
- **去哪一头**：怪物**出生时**（包括每次重生）抽一次：**70% 去左边（车尾）**，30% 去右边（车头）。🟡 左边的几率做成参数。抽到后这辈子都不变，死了重生再重新抽。
- 8 和 10 的缓冲：没在追的时候，距离 ≤ 8 开始追；正在追的时候，距离 > 10 才放弃。两者之间保持原来的状态。
- **被墙挡住时沿墙滑**：现在 `Cast` 挡住后就停下。改成：碰到东西时，把剩下的移动量投影到碰撞面的切线方向上，继续滑动（例如怪在车的正上方要去车尾，会沿着车顶的墙往左滑，绕过车角）。不做正式寻路。
- 追到玩家、到达车头 / 车尾时：贴着停下，不打人、不扣血。
- 门洞挡板、速度、击退、受伤、死亡、重生等其他行为**都不改**。

## 结构要求
- "该往哪走"的判断放进**新脚本**（例如 `MonsterTargeting`），`Monster` 只负责移动、受伤、死亡。`Monster` 每次物理帧向它要目标位置。
- 把判断逻辑写成**纯函数 / 纯 C#**（例如"根据玩家在不在车里、距离、当前是否在追，返回新的追 / 不追状态"），方便测试。
- 车头、车尾的目标点由 `TruckArea` 提供：只新增**一个**小的公开方法（例如 `EndPoint(bool front)`），其他代码不动。
- 不在 `Update` / `FixedUpdate` 里 `Find` / `GetComponent`；玩家和餐车的引用由场景生成器接好。

## 范围限制
- 不做：武器、攻击、掉落、怪物打人、餐车血量、正式寻路、怪物排队。
- 不改受伤、击退、死亡、重生、门洞挡板的行为。
- 设计上有不清楚的地方，写进回报的"疑问"，不要自己决定。

## 给用户的试玩步骤
1. 菜单 `MMF → Build Prototype Scene` → Play。
2. 待在车里：怪物都跑到车的左右两头（多数在左边），门口没有怪。
3. 出车走向一只怪：靠近后它会追你；跑远它就回车头 / 车尾；你回到车里，它们也回车头 / 车尾。
