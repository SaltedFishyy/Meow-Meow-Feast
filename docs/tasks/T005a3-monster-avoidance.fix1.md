# T005a3 补丁 1 — 车边迎面相撞仍然卡死

> 给 Codex：先读 `AGENTS.md`，再读 `docs/tasks/T005a3-monster-avoidance.md` 和你的回报 `docs/tasks/T005a3-monster-avoidance.report.md`。T005a3 的代码已在工作区（未提交），60 个测试通过。

## Claude 实测（Play，玩家在车里）
把两只怪放在车底下：A 在 (−4, −4.1)，要去右边（车头）；B 在 (4, −4.1)，要去左边（车尾）。1 秒后它们在下门正前方撞上，A 停在 (−0.40, −3.91)，B 停在 (0.40, −3.91)，之后 20 秒一动不动。

### 原因 1（主要）：路线计算在车边"安全区"里失效
- 这时 A 从 `MonsterTargeting.TargetPosition` 拿到的目标是**直接去终点 (6.50, 0.00)**，没有走车角。
- 车外框加上 padding（怪物半宽 0.4 + 0.1）以后，下边界是 y = −4.0。可是怪物贴着车底墙走时，中心在 y ≈ −3.9，也就是在这个安全区**里面**。`NextWaypoint` 的起点在安全区里时，`CrossesInterior` 判断为"没穿过"，直接返回终点。
- 结果 A 的移动方向是斜着往上（朝 (6.5, 0)），顶着车底墙。挡住它的是**墙**，不是怪物，所以 `IsBlockedByMonster` 返回 false，避让没有触发，A 就卡住了。B 同理。
- 实测 Cast：A 往右、往下都碰到 B（d = 0），往上是墙。

**要修**：起点在安全区里面（但不在车里）时，路线计算也要正确。例如：把起点看成在安全区边界上（投影到最近的那条边），按"沿着外框走到合适的车角，再去终点"来算。不能直接返回终点。请为这种情况加测试（起点 (−0.4, −3.9)，终点车头外侧 → 下一个路径点应该是右下角，不是终点）。

### 原因 2：贴墙迎面相撞时，两只都往同一边让
- A 往右走（+x），右手边是下（−y），通的，就往下让。
- B 往左走（−x），右手边是上（+y），是墙，按规则改往左手边让，也就是下（−y）。
- 两只同时往下挪，还是面对面，等于没让开。
- **要修**（简单办法）：避让时，如果对面那只怪也正在往**同一个方向**横移，就只让一只让、另一只原地等一下。例如：右手边被挡住、只好改往左让的那只，改成**原地等**避让时长，让对方先过去。只有当对方不动或者不在避让时，它才往左让。
- 这条判断也放进 `MonsterAvoidance`（纯 C#），加测试。
