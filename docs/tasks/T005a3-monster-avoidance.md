# T005a3 — 怪物之间的简单避让（不再迎面卡死）

> 给 Codex：先读 `AGENTS.md`（尤其是 "Good structure, minimal changes"），再读本说明书，再读 `docs/GDD.md` §5.8.1 里"怪物之间互相挡住，撞上时会避让"那一条。T005a、T005a2 已完成并提交。
> 这是**小任务**，只做"怪物撞上别的怪物时让一让"。不做武器（T005b）、掉落（T005c）。

## 问题
Claude 实测：两只怪在车的下墙外面走同一条路，一只往右、一只往左，迎面相撞后互相挡住，卡死不动（位置大约 (−2.2, −4.1) 和 (−1.4, −4.0)）。用户要求怪物之间**继续互相挡住**（不能互相穿过），但要会**避让**。先做简单版本。

## 规则
- 怪物移动时，如果挡住它的是**另一只怪物**（不是墙、不是玩家），就**往自己移动方向的右手边**横移让开，等前方不再被那只怪挡住，再回到原来的路线。
- 两只迎面相撞时都往各自的右手边让，就会错开。
- 右手边也被挡住（例如贴着车墙），就改往**左手边**让。
- 让开的速度和正常移动速度一样，不额外加速。让开的时长或距离做成参数 🟡（例如最多让 0.5 秒，或最多横移 1 单位）。
- 被**墙**挡住时，还是用原来的"沿墙滑"和"绕车角"，不变。被**玩家**挡住时也不变（贴着玩家停下）。
- 不做正式寻路，不做群体排队。车头、车尾挤成一团时互相挡住、停下来，这是可以的。

## 结构要求
- "该往哪边让"的判断写成**纯 C#**（新文件，例如 `MonsterAvoidance`，可以是静态方法），输入当前移动方向、右边能不能走、左边能不能走，输出避让方向，方便测试。
- `Monster` 只做最小改动：在已有的 `Cast` 结果里分辨"挡住我的是不是另一只怪物"（例如看命中的 collider 上有没有 `Monster` 组件。**不要在 `FixedUpdate` 里每帧 `GetComponent`**：可以用 `TryGetComponent`，只在真的被挡住时调用；或者用别的不产生分配的办法），被怪物挡住时调用避让逻辑。其他逻辑（受伤、击退、死亡、沿墙滑、目标选择）不动。
- 参数放进 `MonsterDefinition`。

## 范围限制
- 不做：武器、掉落、怪物打人、餐车血量、正式寻路、排队。
- 不改目标选择、受伤、击退、死亡、重生、门洞挡板。
- 设计上有不清楚的地方，写进回报的"疑问"，不要自己决定。
