# T009c — 被打中弹开一点 + 1 秒无敌（一闪一闪、能穿过怪物）

> 给 Codex：先读 `AGENTS.md`（尤其是 "Tunable gameplay values (数值)"），再读本说明书和 `docs/GDD.md` §5.3.2。
> T009a、T009b 已完成并提交：`PlayerHealth`（`TakeHit(damage, direction)`、`CanBeHit`、`Changed`）、`MonsterAttack`（扑出那一刻判断 `CanBeHit`，`direction` = 怪物指向玩家的方向）、左上角血量方块。
> 这是**小任务**：只做"被打中以后"的反应。**不做**：血归零倒地 / 复活（T009d）、餐车（T009e）。

## 目标
- **弹开**：被打中（真的掉了血）时，玩家沿 `direction`（就是"从怪物指向玩家"的方向）被推开"被打弹开多远"（默认 **0.5** 格 🟡），在很短时间内滑过去（时长是外观，序列化字段，默认 0.1 秒）。弹开会被墙、餐车墙、锅台挡住（不能穿墙）。弹开期间玩家自己的 WASD 不起作用，弹完马上恢复。
- **无敌**：被打中后"被打后无敌几秒"（默认 **1** 🟡）内：
  - 不会再掉血（`CanBeHit` 为 false，所以怪物不会开始蹲、扑出去也是扑空）。
  - **能穿过怪物**：玩家和怪物不互相挡；玩家往怪物身上走时**不挤怪物**（`PlayerShove` 不推、也不减速）；怪物也不因为贴着玩家而停住。
  - 角色**一闪一闪**（例如渲染器透明度在两档之间切换；闪的快慢、透明度是外观，序列化字段）。结束时恢复原样。
- **无敌结束时还和怪物重叠**：掉血的无敌照常结束（能再被打），但**穿怪继续**，直到玩家不再和任何怪物重叠，才恢复互相挡住（避免卡在怪物里）。
- 血已经到 0：这次只是不再被打（和 T009a 一样），倒地是 T009d，不用管。

## 要做的事
1. **`PlayerHealthTuning`**：加 2 个字段（`TuningLabel` 中文名、`Min(0)`）：
   | 字段 | 中文名 | 默认值 |
   |---|---|---|
   | `_knockbackDistance` | 被打弹开多远 | 0.5 |
   | `_invincibleSeconds` | 被打后无敌几秒 | 1 |
2. **`PlayerHealth`**：真的掉血后进入无敌（`CanBeHit` 同时要求不在无敌中），并发出一个"被打中"事件（带方向），给下面的反应脚本用。无敌计时放这里还是反应脚本里你选清楚的一种，回报写明。以后复活也要用同样的无敌（T009d），所以留一个公开的"开始无敌"方法。
3. **新脚本 `Scripts/Player/PlayerHitReaction.cs`**：只管弹开、闪烁、穿怪（开 / 关和怪物的碰撞，处理"结束时还重叠"）。
4. **穿怪需要改的地方**（只改最少的部分）：
   - `PlayerShove`：穿怪时不推怪物、不减速。
   - `Monster.cs`：`LimitDynamicContact` 等对玩家的检测在穿怪时忽略玩家（不然怪物会贴着玩家停下）。用什么方式让怪物知道"现在可以穿过玩家"你选（例如物理层 / `Physics2D.IgnoreCollision` 后再在查询里过滤，或一个只读的状态），回报写明。
   - `PlayerMovement`：如果弹开需要它让出控制，只加最小的接口（类似已有的 `SetBlocked`）。
5. **生成器**：给玩家加 `PlayerHitReaction`，填引用。已有的 `PlayerHealthTuning.asset` 不覆盖。

## 验收标准
- [ ] 编译无报错无警告；场景生成 3 次，引用都不为空；93 个测试全部通过
- [ ] 被怪物扑中：血 -1，玩家往远离怪物的方向弹开约 0.5 格，然后一闪一闪约 1 秒
- [ ] 无敌期间：旁边的怪物不蹲不扑（或扑空），血不变；能直接走穿怪物，走过去时不减速、怪物不被推动
- [ ] 无敌结束时站在怪物里：能继续走出来，出来以后又和怪物互相挡住
- [ ] 背对墙被打：弹开被墙挡住，不穿墙
- [ ] 1 秒后可以再次被打中（再 -1、再弹开、再闪）
- [ ] 数值窗口"玩家血量"组多了 2 个数值，Play 中改了下一次被打就生效
- [ ] 不被打的时候：挤怪物（速度减半、怪物被推开）、怪物贴着玩家停下等原来的行为不变
