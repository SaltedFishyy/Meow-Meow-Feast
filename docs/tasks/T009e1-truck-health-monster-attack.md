# T009e1 — 餐车 100 滴血，怪物在车头 / 车尾用"蹲一下再扑"打车

> 给 Codex：先读 `AGENTS.md`（尤其是 "Tunable gameplay values (数值)"），再读本说明书和 `docs/GDD.md` §5.8.1"攻击"、§5.8.3"餐车血量"。
> T009a～d 已完成并提交：`MonsterAttack`（追玩家时：发现 → 蹲 → 扑 → 冷却，只打玩家）、`PlayerHealth`、倒地复活。
> 这是**小任务**：只做餐车血量和怪物打车的**规则**。**不做**：顶部中间的餐车血条（T009e2）、车血 0 的失败画面（T009f）。

## 目标
- **餐车血量**：开局满血 **100** 🟡（"餐车最多几滴血"）。被怪物打一下掉"打车每下伤害"（默认 **1** 🟡）。最低 0；到 0 这次**什么都不做**（失败是 T009f），只是不再掉血、怪物也不再打车。
- **怪物打车**：用和打玩家**完全同一套**"发现 → 蹲 → 扑 → 冷却"（同样的攻击范围、提示时间、冷却），只是目标换成餐车：
  - 只在怪物**不追玩家**（正去 / 已在车头车尾）时打车。
  - 只打**它这辈子要去的那一头**：去车尾（左）的怪物，自己在车尾外墙的左边（怪物中心 x ≤ 车外墙左边 x）；去车头（右）同理。走在车门那两侧绕路时**不打车**。
  - 发现条件：怪物碰撞体边缘到**车外墙那一面**的距离 ≤ 攻击范围、冷却已结束、餐车血 > 0。
  - 扑：朝车（水平朝车中心方向）扑一段，碰到车墙就停（和打玩家一样用现有的会被碰撞挡住的移动）。扑出那一刻还在范围里 → 车掉血；否则扑空。
  - 怪物正在蹲 / 扑车时，玩家出车走近：**这一下照常打完**（打的还是车），冷却后再按"追玩家优先"判断。蹲 / 扑玩家时玩家进车：照旧扑空（T009a 的规则）。
- 车血到 0 以后怪物不再蹲（贴着车停着）。

## 要做的事
1. **新数值文件 `Scripts/Data/TruckTuning.cs`**：`[TuningGroup("餐车", 10)]`，`_maxHealth`（中文 `餐车最多几滴血`，默认 100，`Min(1)`）。生成器"只在缺失时创建"（参考 `LoadPlayerHealthTuning`）。
2. **`MonsterDefinition`**：加 `_truckDamage`（中文 `打车每下伤害`，默认 1，int，`Min(0)`）。
3. **新脚本 `Scripts/Truck/TruckHealth.cs`**：只管车血：`Current`、`Max`、`CanBeHit`（血 > 0）、`TakeHit(int damage)`、`Changed` 事件（给 T009e2 的血条用）、`Destroyed` 或类似的"到 0"事件（给 T009f 用；如果你觉得现在加没人订阅的事件不好，就不加，回报写明）。
4. **`MonsterTargeting`**：加只读属性，让别人知道"现在是不是在追玩家"、"要去哪一头"（`_front`）。
5. **`MonsterAttack`**：加"打车"这个目标，和打玩家共用同一套状态和计时，不要复制一份。**顺手**把它自己那份"在不在追"的判断（`_chasing` + `ShouldChase`）删掉，改用 `MonsterTargeting` 的新属性（同一个物理帧、同样的输入，行为不变；避免两份状态）。
6. **生成器**：给车加 `TruckHealth`、填引用；怪物填新引用。已有数值文件不覆盖。
