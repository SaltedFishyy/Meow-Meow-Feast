# T011a — 怪物在车边先等 8～12 秒，再扑车一下

> 给 Codex：先读 `AGENTS.md`（尤其是 "Tunable gameplay values (数值)"），再读本说明书和 `docs/GDD.md` §5.8.4（怪物打车的节奏）。
> T009e1 已完成并提交：`MonsterAttack` 在怪物不追玩家、到了自己那一头、边到车外墙 ≤ 攻击范围时，就按"蹲 → 扑 → 冷却"一直打车。
> 这是**小任务**：只加"先等、只扑一下、再等"。**不做**：扑完以后四处走动（T011b）。这一步做完时，怪物扑完一下会**留在原地重新等**（T011b 再改成走开）。

## 目标
- 怪物不追玩家、到了自己那一头、在打车范围内（就是现在 `MonsterAttack` 判断"可以打车"的同一个条件）时，**先等**一段时间，再开始"蹲 → 扑"打车：
  - 等多久：每次在"车边最少等几秒"和"车边最多等几秒"之间**随机**（默认 **8** 和 **12** 🟡）。
  - 计时从怪物**第一次**满足"可以打车"的那一刻开始。等的时候怪物贴着车不动（和现在贴着车一样），没有额外提示。
  - 等的时候怪物被挤开 / 被打后退、暂时离开了范围：**计时不清零**，回到范围里接着等（不要因为被推一下就重新等）。
- 等完 → 照现在的规则**蹲（闪 0.5 秒）→ 扑一下**打车（扑中扣血、扑空就算了）。
- 扑出去以后 → 重新随机一个等待时间，**从头再等**（T011b 会改成"去走动"）。
- **开始追玩家**时（`MonsterTargeting.IsChasingPlayer` 变成 true）：等待状态全部清掉。之后再不追玩家时，从"去车边 → 等"重新开始。
- 怪物死了 / 重生：等待状态清掉。
- 打玩家的规则（T009a～c）**完全不变**。原来的"攻击冷却"对打车仍然有效，但等待时间远比冷却长，所以实际上不起作用。

## 要做的事
1. **`MonsterDefinition`**：加 2 个字段（`TuningLabel` 中文名、`Min(0)`）：
   | 字段 | 中文名 | 默认值 |
   |---|---|---|
   | `_truckWaitMin` | 车边最少等几秒 | 8 |
   | `_truckWaitMax` | 车边最多等几秒 | 12 |
   最多 < 最少时按"最少"算（不要报错）。
2. **新脚本 `Scripts/Combat/MonsterTruckRoutine.cs`**：只管"打车的节奏"状态（这次只有：去车边 / 等 / 可以打）。对外提供例如 `CanAttackTruck`（等完了没有）和 `OnTruckAttackLaunched()`（扑出后调用）。T011b 会在这里加"走动"状态，所以状态要写得容易扩展（例如一个枚举）。
3. **`MonsterAttack`**：打车前多问一句 `CanAttackTruck`，扑车出手时通知 `OnTruckAttackLaunched()`。"在不在打车范围"的判断如果 `MonsterTruckRoutine` 也要用，就共用一份（例如改成 `internal`），不要复制。
4. **生成器**：给每只怪物加 `MonsterTruckRoutine`，填引用。已有的 `CursedDumpling.asset` 不覆盖。
